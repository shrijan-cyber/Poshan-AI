## Interpretation

- The public-apis directory is a discovery list, not verification. Its own MIT license does not apply to indexed APIs.
- Generic nutrition-analysis APIs calculate from their own catalogs and heuristics; they do not provide verified IFCT-level identity, source version, raw/cooked basis and provenance.
- A branded label is not a substitute for raw ingredient composition. Open Food Facts should remain a separate branded-food namespace because of both semantic and ODbL concerns.
- API rates, pricing and terms above reflect first-party pages reviewed on the date shown and can drift. Where official details could not be verified, the table says so instead of estimating.

## Decision

Do not add external nutrition APIs to the authoritative meal-plan path. Continue IFCT staging only with source provenance and null preservation. The sole product-facing API candidate is Open Food Facts for a future barcode feature, subject to license review, separated storage, user-visible package/label source, and stale/missing data handling. No API is approved for medical advice or diagnosis.
