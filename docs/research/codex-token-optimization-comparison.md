# Codex token-efficiency tools: repository evaluation

**Reviewed:** 5 November 2026. **Environment:** Windows 11, VS Code, Codex, PoshanAI. Research and local file-size POC only; no tool was installed, no Codex/global config was modified, and no project source was transmitted.

## Executive recommendation

**Best repository candidate: Capsule**, because it directly targets terminal output, repeated reads, project context, and Codex MCP workflows while documenting exact evidence recovery and Windows support. Its broad MCP action surface and bundled lifecycle hooks are meaningful risks, so this is a candidate recommendation, not approval to install. First shrink the always-read instruction surface using the hierarchy in [the POC report](codex-context-efficiency-poc.md). Do not install multiple compressors.

No external compressor was run against PoshanAI. “Actual savings” below distinguish repository-published, workload-specific measurements from this repository’s byte-count POC. No quality comparison or response-quality claim was measured.

## Capability comparison

| Goal | Best fit | Caveat |
|---|---|---|
| Reduce repeated context between turns | Capsule; Compaction | Both change model-visible context. Exact bytes do not prove semantic/task preservation. |
| Compress terminal output | Capsule or lowfat | lowfat is narrower and simpler; high compression may hide evidence. Capsule has local exact recovery but more privileged functionality. |
| Reduce file-reading overhead | Capsule; CodeSight wiki/articles | CodeSight output is derived and can go stale; always open source for high-risk edits. |
| Project indexing / impact map | CodeSight or Capsule | Overlapping feature; do not run both by default. |
| Codex integration | Capsule, Compaction, CodeSight (manual MCP) | Hooks/global config require approval; Compaction Windows support is unverified. |
| Windows reliability | Capsule has explicit Windows claim; CodeSight/lowfat are plausible but local tests absent | None was exercised on this machine. |
| Privacy | local-only tool reduces additional vendor exposure, not model-provider exposure | Local indexes, caches, receipts, and recovery blobs can contain sensitive source/output. |
| Maintenance | Capsule provides versioned releases/tests; CodeSight and lowfat have active repo docs; Compaction has vendor-managed CLI/engine | Project activity is not a support SLA. Pin versions and rerun tests. |

## Selected profile

1. **P0, no install:** reduce auto-loaded project instruction/context. Keep repository invariants in root `AGENTS.md`; read `PRODUCT.md`, `DESIGN.md`, `AI_CONTEXT.json`, `PROJECT_AI_GUIDE.json`, and architecture docs only when task-relevant. Replace repeated full-document instructions with section links and task-specific reads in a separately reviewed change.
2. **P1, candidate after approval:** Capsule local MCP, initially with no lifecycle hooks/global hooks. Verify whether the selected plugin registration can omit hook definitions; if not, do not trust/enable those hooks. Restrict MCP tools to read-only until required. Pin the release and inspect manifest, permissions, source and privacy behavior.
3. **No complementary compressor initially:** CodeSight, lowfat and Compaction overlap. Use one only if a measured gap remains after the instruction cleanup and Capsule trial.

Detailed local comparison and a safe POC plan are in [codex-context-efficiency-poc.md](codex-context-efficiency-poc.md).
