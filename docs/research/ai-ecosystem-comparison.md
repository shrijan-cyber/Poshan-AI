# PoshanAI AI ecosystem comparison

**Reviewed:** 5 November 2026. Research only; no external repository was installed. Repository claims are separated from provider guarantees. Provider/model status changes quickly; verify before enabling a route.

## Current PoshanAI baseline

The active app is JavaScript MERN: React/Vite, Express, Mongo/Mongoose, with optional Redis/BullMQ. There is no active Python AI service. `aiFoodParserService.js` sends diary text and the IFCT catalog to an OpenAI-compatible endpoint; recipe instructions use `aiService.js`; plan selection and IFCT nutrition arithmetic stay deterministic in `dietService.js`/`recipeCatalog.js`. OCR is local Tesseract/PDF.js (`ocrProcessor.js`), while report workflows persist extracted data. Do not infer that OCR implies a safe external report-AI integration. The existing backend route defaults to `gemini-2.0-flash`, which Google lists as shut down; the legacy route needs an operator-selected live model before it can be considered operational. No production route was changed here. [Google model lifecycle](https://ai.google.dev/gemini-api/docs/models)

## Comparison by engineering dimension

- **Discovery and quality:** Awesome lists are indexes, not quality benchmarks. No listed model should be selected by marketing claims alone. PoshanAI needs a fixed synthetic recipe corpus, schema pass rate, ingredient match rate and latency measurement.
- **Cost and quotas:** “Free” is an account/provider policy, not an SLA. Google’s published free-tier pricing states that free-tier content may be used to improve products, whereas paid-tier content is not used that way; do not send health data to free-tier experiments. [Gemini pricing](https://ai.google.dev/gemini-api/docs/pricing)
- **Reliability/context:** Query the active provider’s model list and quota page at test time. OmniRoute model capability is upstream-specific. Avoid context-heavy architectures: recipe instruction requests are small and bounded.
- **Structured output:** Gemini supports a subset of JSON Schema in its API; OmniRoute translates only where selected provider supports it. Backend Joi validation remains mandatory. [Gemini structured output](https://ai.google.dev/gemini-api/docs/structured-output)
- **Node fit:** Existing endpoint uses native `fetch`, Joi, Winston and environment config; adding LangChain/Python or a second gateway provides no demonstrated need.
- **Maintenance/licensing:** A curated list is not a dependency. OmniRoute MIT does not license upstream APIs/models. FCC AGPL is acceptable for private local evaluation subject to terms, but legal review is needed before distributing/modifying a network service.

## Prioritized decision

| Priority | Recommendation | Benefit / effort | Key risk and cost |
|---|---|---|---|
| P0 | Replace the shut-down default model with a currently available, explicitly approved production model in a separate change; verify endpoint/model/key in a controlled smoke test. | Restores potential AI route / low effort after selection. | Do not guess model availability or enable a free tier with unsuitable data terms. |
| P0 | Keep nutrition calculations, food eligibility, recipe selection, health rules and report values deterministic/validated. | Protects data correctness / ongoing tests. | No direct API cost; requires regression coverage. |
| P1 | Keep current optional, recipe-only OmniRoute POC; evaluate on synthetic data before production approval. | Tests gateway fit / low-medium effort. | Adds gateway/upstream privacy surface and operations. |
| P1 | Instrument sanitized latency, outcome, schema-validity and provider usage metrics without prompts, names, food diaries or health data. | Makes cost/reliability measurable / medium. | Usage metadata may be absent; no reliable cost estimate then. |
| P2 | Use Awesome-LLM and free API list as discovery references only. | Broader research / low. | Staleness and provider policy churn. |
| P3 | Defer FCC install and additional LLM gateways. | Avoids global config and duplicate routing risk. | No measured cost or quality improvement yet. |
